# 60 SECOND : HOME

마트에서 집까지 단 60초. 물자를 챙기고, 가족을 선택하고, 하루씩 버티며 탈출할 길을 찾는 한국어 좀비 생존 게임입니다. 기존 저장소에 기술 스택이 없어 **Vite + 순수 JavaScript / CSS / SVG**로 구현했습니다. 서버·데이터베이스·API 키·외부 이미지나 폰트 없이 실행됩니다.

## 웹으로 배포하기 (GitHub Pages)

한 번 설정하면 `main`에 푸시할 때마다 규칙 테스트 → 프로덕션 빌드 → GitHub Pages 배포가 자동으로 실행됩니다. 배포된 페이지에서는 설치나 파일 다운로드 없이 시작 버튼으로 바로 플레이할 수 있습니다.

1. 저장소의 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 선택합니다.
2. **Actions → Deploy game to GitHub Pages → Run workflow**로 첫 배포를 실행합니다. 이후에는 `main` 푸시로 자동 갱신됩니다.
3. 워크플로의 `deploy` 작업이 성공하면 **https://dpsej0129.github.io/60second/** 를 엽니다. 실제 배포 완료 여부는 Actions 결과 또는 Settings → Pages에서 확인합니다.

`.github/workflows/deploy-pages.yml`이 배포를 담당합니다. Vite의 상대 에셋 경로로 프로젝트 하위 주소에서도 CSS와 JavaScript를 불러옵니다. `npm run test:deploy`는 실제 빌드를 `/60second/` 아래에 올려 스타일 로드와 시작·수집·귀가를 검사합니다. 도메인 루트에 정적 호스팅할 때도 같은 `dist/` 폴더를 사용할 수 있습니다. 로컬 세이브의 최장 기록은 접속 도메인별로 보관됩니다.

## 바로 플레이하기 (설치 불필요)

이 저장소의 **Code → Download ZIP**으로 내려받아 압축을 푼 다음, `downloads/60second.html`을 Chrome·Edge·Firefox로 여세요. 서버 주소에 접속하거나 Node.js를 설치할 필요가 없습니다. GitHub의 HTML 코드 화면 자체에서는 게임이 실행되지 않습니다.

`downloads/60second.html`은 현재 소스에서 생성해 함께 커밋한 독립 실행 파일입니다. 소스를 수정한 뒤에는 `npm run build:offline`을 실행하고 생성된 `dist/60second.html`을 `downloads/60second.html`에 복사하면 갱신할 수 있습니다.

## 실행

Node.js 22.12 이상(권장: 24 LTS)과 npm이 필요합니다.

```sh
npm ci
npm run dev
```

브라우저에서 개발 서버의 주소를 엽니다. 기본 포트는 5173이며 `npm run dev -- --port 3000`처럼 바꿀 수 있습니다.

```sh
npm run build       # dist/ 정적 배포 파일 생성
npm run preview     # 빌드 결과 실행
npm test            # 게임 규칙 / 시드별 캠페인 검증
npm run test:browser # 실제 Chromium에서 두 결말까지 UI 조작
```

npm 캐시가 쓰기 제한된 클라우드에서는 `npm ci --cache /tmp/60second-npm`을 사용할 수 있습니다. 브라우저 테스트는 기본적으로 `/usr/bin/chromium`을 사용합니다. 다른 위치라면 `CHROMIUM_PATH=/path/to/chromium npm run test:browser`를 사용하세요. 테스트가 임시 Vite 서버를 띄우고 종료하며, 스크린샷은 무시되는 `test-results/`에 저장됩니다. 이미 실행 중인 서버는 `GAME_TEST_URL`로 지정할 수 있습니다.

## 플레이

1. **첫 보급**: 시작 버튼을 누르면 마트에서 60초가 시작됩니다. 진열대의 물품을 클릭하면 해당 지점으로 이동한 뒤 0.8초 동안 수집합니다. 빈 바닥 클릭, WASD 또는 방향키로도 이동할 수 있고, E로 가까운 물품을 수집합니다. 벽과 진열대는 통과할 수 없습니다. 추격자에게 닿거나 집 밖에서 시간이 끝나면 패배합니다.
2. **네 칸의 선택**: 물품 옆 숫자는 필요한 칸 수입니다. 가방 안 물품을 클릭하면 진열대로 반환합니다. 집 아이콘 또는 귀가 버튼을 눌러 돌아오면 전부 집 재고로 옮겨지고 가방이 비워집니다.
3. **가족**: 첫 귀가 때 지우(간호), 준(정비·방어), 은(관찰)을 각각 데려올지 선택합니다. 데려온 사람마다 하루 식량 1인분과 물 1인분이 추가로 필요합니다. 가족 선택 중에는 시간이 흐르지 않습니다.
4. **하루의 생존**: 사람별 식량·물 체크박스로 배급을 정하고, 필요하면 치료한 뒤 다음 날로 진행합니다. 재고가 부족하면 화면 위의 사람부터 배급합니다. 허기 3일째부터 체력 −1, 갈증 2일째부터 −2, 부상은 매일 −1입니다. 체력이 0인 가족은 사망하고, 플레이어가 사망하면 패배합니다. 음식·물은 해당 결핍 일수를 0으로 돌리지만 체력은 회복하지 않습니다. 구급약은 체력 2 회복과 부상 치료(지우가 생존하면 체력 3 회복), 한 번에 1회분을 사용합니다.
5. **반복 보급**: 집에서 출발하는 순간부터 새로운 60초가 시작됩니다. 마트까지 가는 길, 수집, 귀가가 모두 포함됩니다. 출발 직후 문 앞에 서 있는 것만으로 귀가 처리되지는 않습니다. 마트의 재고는 소모되며 다시 채워지지 않습니다. 보급은 그날 안에 진행되고, 날짜는 배급 버튼으로만 넘어갑니다.
6. **사건과 결말**: 사건 선택을 해결한 뒤 다음 행동을 정합니다. 오른쪽의 ‘살아나갈 길’에서 열린 경로와 준비할 물자를 확인하세요. 날짜만 넘겨서는 승리할 수 없습니다. 결말·패배 화면에서 새 게임을 시작할 수 있습니다.

보급 중에는 도움말을 열거나 다른 탭으로 이동해도 시간이 계속 흐릅니다. 현재 판의 진행은 메모리에 있으며 새로고침하면 새 게임이 됩니다. 최장 생존 일수만 로컬 저장소에 보관합니다(저장소 접근이 차단되어도 플레이 가능).

### 물품

집의 시작 재고는 식량 8인분 / 물 8인분입니다.

| 물품          | 가방 | 귀가 후 재고 / 기능           |
| ------------- | ---- | ----------------------------- |
| 통조림        | 1칸  | 식량 4인분                    |
| 비상식량 상자 | 2칸  | 식량 10인분                   |
| 생수 묶음     | 1칸  | 물 4인분                      |
| 대형 물통     | 2칸  | 물 10인분                     |
| 대형 구급상자 | 2칸  | 치료 4회분                    |
| 휴대용 무전기 | 2칸  | 구조 무전에 응답 가능, 재사용 |
| 공구 세트     | 1칸  | 방어 또는 공동체 수리 1회     |

### 두 승리 경로

- **새벽의 구조**: 마트에서 무전기 확보 → 구조 신호에 응답 → 후속 무전에서 살아 있는 인원수만큼 식량과 물 전달 및 신호 보내기 → 마지막 호출에 탑승. 은이 없으면 신호를 보내다가 플레이어가 부상합니다.
- **함께 만드는 내일**: 이웃 제안에 교섭 시작 → 후속 사건에서 준 또는 공구 1개로 펌프 수리, 혹은 식량 4 + 물 4 기부 → 최종 초대에 합류.

준비가 부족하면 사건을 연기할 수 있으며 기회는 다시 발생합니다. 열린 경로의 조건은 현재 생존 인원과 재고로 확인하고, 자원을 실제로 전달한 뒤에만 마지막 단계가 열립니다.

### 사건 공백과 후속 사건 보장

- 시드가 있는 난수 생성기로 초기 사건 날짜와 각 단계의 후속 날짜를 정합니다. 기본 시드는 새 게임을 만든 시각입니다.
- 사건이 없는 날은 **최대 2일 연속**입니다. 다음 날에는 조건이 맞는 사건이 반드시 열립니다. 예약이 없으면 경계 사건을 발생시킵니다.
- 후속 단계는 앞 단계의 선택을 해결한 시점에만 예약됩니다(1~3일 후, 연기는 1~2일 후).
- 예약은 발생 예정일과 그로부터 2일 뒤의 우선 처리 기한을 갖습니다. 기한을 지난 사건을 가장 먼저 처리하고, 동시 예약은 하루에 하나씩 순서대로 처리합니다. 따라서 기한이 곧 절대 발생일은 아니지만 후속 사건은 무작위 추첨에 영구히 밀리지 않습니다. 현재 사건 구성에서는 단계 간 최대 7일을 회귀 테스트합니다.
- 구조·합류·습격·부상·거래·경계 사건이 포함되어 있습니다.

## 구조와 검증

- `src/engine.js`: 브라우저와 독립적인 게임 규칙. 경로 탐색, 실제 시간 누적, 추격, 칸 수, 재고 이동, 배급·치료·사망, 가족 효과, 사건 예약과 결말.
- `src/main.js`: 화면과 입력, SVG 지도, 애니메이션, 실제 시간 측정. 긴 프레임도 경과 시간을 버리지 않으며 엔진이 작은 간격으로 충돌을 확인합니다.
- `src/style.css`: 반응형 UI. 작은 화면에서 지도만 내부 스크롤되고 타이머는 상단에 고정됩니다.
- `tests/engine.test.js`: 실제 동선 왕복, 칸 수 및 하역, 제한 시간·추격 패배, 가족 수별 소비, 개별 배급·치료, 가족 능력, 사건 공백 상한, 사건 순서, 두 경로의 난수 시드별 100판씩 도달, 재시작 검증.
- `tests/browser.test.js`: 테스트용 상태 주입 없이 실제 화면을 조작해 보급·하역·가족·배급·추가 보급·두 승리 결말·실패·재시작을 검증합니다. 모바일 폭, 도움말과 브라우저 예외도 확인합니다.

첫 버전은 단일 플레이어 로컬 게임입니다. 그래픽·음향 확장보다 처음부터 결말까지의 플레이 흐름에 집중했습니다.

## 서버 없이 실행하는 버전

`npm run build:offline`은 CSS와 JavaScript를 모두 포함한 `dist/60second.html`을 생성합니다. 다운로드한 파일은 일반 브라우저에서 직접 열 수 있으며 외부 네트워크 요청이 없습니다. `npm run test:offline`으로 독립 HTML의 시작·수집·귀가·가족·일일 배급을 검증합니다. 관리형 클라우드 Chrome은 `file://` 접근을 차단하므로 테스트는 동일 HTML을 빈 페이지에 로드합니다.
